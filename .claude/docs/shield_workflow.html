All HTTP API Endpoints (Safety Shield)

All calls via RunnerHttp (authenticated Dio). Headers include Bearer token. On exception → MonitoringServiceHelper.logError (Coralogix) + ShieldApiResult.failure returned.
POST api/v1/runners/me/sos/initiate RunnerHttp.runnerSOSInitiate · _initiateSosAndShowSheetInternal ▼

Initiates an SOS incident. Called for ALL trigger types (ML, shake, volume, manual, FCM, sync).

Request Body:

{
  "source": "safety_shield" | "sos_slider" | ...,
  "trigger_type": "ml" | "non_ml",
  "job_id": 12345  // optional, included when job active
}

Response (200):

{
  "sos_id": 789   // used to track this SOS incident throughout lifecycle
}

On failure: fires expert_shield_sos_initiate_failed {source, trigger_type, job_id} → both planes. Flow aborted.

POST api/v1/runners/me/sos RunnerHttp.runnerSOS · confirm / deny / dismiss ▼

Unified SOS action endpoint for confirm, deny, and deescalate (dismiss). Called with different user_action values.

Request Body (confirm):

{
  "sos_id": 789,        // from initiate response
  "user_action": "confirm"
}

Response (confirm 200):

{
  "ph_no": "+91XXXXXXXXXX"  // support contact shown in SOSActiveScreen
}

Request Body (deny):

{
  "sos_id": 789,
  "user_action": "deny"
}

Request Body (dismiss/deescalate):

{
  "sos_id": 789,
  "user_action": "dismiss"
}

Also used by sos.dart SOSProvider.triggerSOS(): no sos_id field (legacy slider path).

On deny API failure: fires expert_shield_sos_deny_api_failed {sos_id, source, action_type, error}

GET api/v1/runners/me/sos/active RunnerHttp.runnerSOSActive · syncActiveSosState ▼

Polls backend for current SOS state. Called on job start, app resume, and sync recovery path.

Request: No body. Auth header only.

Response (200):

{
  "has_active_sos": true,
  "sos": {
    "status": "initiated" | "pending" | "resolved",
    "sos_id": 789,
    "ph_no": "+91XXXXXXXXXX"  // optional
  }
}

Routing: "initiated" → _handleSyncInitiated (show alert sheet if not already in SOS mode); "pending" → _handleSyncConfirmed; local=SOS + backend=no SOS → _handleSyncDenied (state desync).

POST api/v1/runners/me/safety-shield/consent ShieldHttp.activateSnabbitShield · ShieldConsentProvider ▼

Records runner consent for shield data collection. Gate 1 of start chain.

Request Body:

{
  "consent": true,
  "consent_version": "1.0"
}

Response (200): success. userProfileProvider.consentGiven = true set locally.

On success: fires expert_shield_consent_given → CleverTap + Mixpanel

GET api/v1/audio/presigned-url ShieldHttp.getPresignedUrl · ShieldUploadQueue ▼

Step 1 of 3-step upload flow. Returns pre-signed S3 URL for direct upload.

Query Params:

job_id=12345×tamp=1718000000&is_sos=true

Response (200):

{
  "presigned_url": "https://s3.amazonaws.com/bucket/...",
  "s3_key": "recordings/job_12345/clip_1718000000.enc",
  "allowed_content_types": ["application/octet-stream"]
}

On 409 (duplicate): row deleted from SQLite, considered done — no retry.

PUT {presigned_url} (S3 direct upload) ShieldHttp.uploadToS3 · ShieldUploadQueue step 2 ▼

Raw PUT to S3 presigned URL. NO auth headers (S3 rejects them).

Headers:

Content-Type: application/octet-stream
Content-Length: {bytes.length}

Body: Raw encrypted + gzip-compressed bytes (AES-256-GCM output)

Timeouts: sendTimeout=2min, receiveTimeout=2min

Returns: true if status 200. Any exception → _retryOrDrop.

POST api/v1/audio/upload-complete ShieldHttp.confirmUpload · ShieldUploadQueue step 3 ▼

Step 3: Confirms upload succeeded and provides encryption metadata for backend decryption.

Request Body:

{
  "job_id": 12345,
  "timestamp": 1718000000,
  "s3_key": "recordings/job_12345/clip_1718000000.enc",
  "is_sos": true,
  "encryption": {
    "algorithm": "AES-256-GCM",
    "iv": "base64_encoded_12_bytes",
    "auth_tag": "base64_encoded_16_bytes",
    "wrapped_key": "base64_RSA_OAEP_SHA256_wrapped_AES_key",
    "key_algorithm": "RSA-OAEP-SHA256"
  },
  "duration_seconds": 10,
  "file_extension": "m4a",
  "is_compressed": true
}

Response (200 or 409): success. SQLite row deleted. Fires expert_shield_upload_success.

On failure: _retryOrDrop → exponential backoff → max 5 retries → expert_shield_upload_dropped.

Pending Listener Queue (SafetyMonitoringService)

When listener==null (Flutter engine temporarily detached or notifyStreamsReady not yet called), all notifyListener{} calls are stored in pendingListenerCalls (synchronizedList). Queue flushed when notifyStreamsReady() sets the listener. This ensures no instrumentation or SOS events are dropped during hot restart or engine reattach.
