## 🚀 Quick Start Guide

### Running Tests

```bash
# Run all tests
make test

# Run tests with coverage report
make test-cov

# Check coverage for YOUR changes only (recommended before PR)
make test-my-changes

# Enforce coverage requirements (run before commit)
make coverage-check
```

### Generating Tests

```bash
# Generate test scaffolds for any Dart file
make generate-test FILE=lib/models/my_model.dart

# The agent will:
# 1. Analyze your code (enums, extensions, classes, functions)
# 2. Detect methods (factory, static, instance)
# 3. Count branches (if/else, switch, ternary, null checks)
# 4. Generate test scaffolds following AAA pattern
# 5. Create builder file if needed
# 6. Add appropriate imports
```

### Test Development Workflow

```bash
# 1. Generate scaffolds
make generate-test FILE=lib/models/wallet.dart

# 2. Review generated tests
# - Check what was detected
# - Review TODO comments
# - Verify branch counts

# 3. Fill in TODOs
# - Add specific assertions
# - Add edge case tests if needed
# - Implement builder JSON methods

# 4. Run tests
make test

# 5. Verify coverage
make coverage-check

# 6. Commit with confidence!
git add . && git commit -m "Add tests for wallet module"
```

## 📊 Testing Philosophy

### Coverage Requirements

| Module Type | Line Coverage | Branch Coverage | Rationale |
|-------------|---------------|-----------------|-----------|
| **Payment** | 80% | **100%** | Money = critical |
| **Wallet** | 80% | **100%** | Money = critical |
| **Referrals** | 70% | **100%** | Business logic |
| **Services** | 70% | **100%** | API integration |
| **Providers** | 70% | **100%** | State management |
| **Models** | 60% | **100%** | Business logic only |
| **Pages** | 60% | **100%** | User flows |
| **Widgets** | 50% | **100%** | UI logic |

**Key Principle**: **100% branch coverage is NON-NEGOTIABLE**

### What to Test

✅ **MUST Test** (100% branch coverage):
- Business logic (calculations, validations, state changes)
- All switch/case statements
- All if/else branches
- Try/catch blocks
- Ternary operators
- Null checks and null coalescing
- Error handling paths
- Edge cases (null, empty, boundary values)

⚠️ **NICE to Test** (contributes to line coverage):
- Simple getters/setters
- Constructor assignments
- Pass-through methods

❌ **DON'T Test**:
- Generated code (*.g.dart, *.freezed.dart)
- Third-party library code
- Pure UI layouts (no logic)
- Constants/enums without methods

## 🛠️ Advanced Patterns

### Builder Pattern with Sentinel Class

**Problem**: Need to distinguish "use default" from "explicit null"

**Solution**: Sentinel pattern
```dart
class _Default { const _Default(); }

static Map<String, dynamic> jsonWith({
  Object? amount = const _Default(),  // Can be int, null, or default
}) {
  if (amount is! _Default) {
    json['amount'] = amount;  // Allows explicit null
  } else {
    json['amount'] = 100;  // Use default only when sentinel
  }
}

// Usage:
jsonWith()              // → amount: 100 (default)
jsonWith(amount: null)  // → amount: null (explicit)
jsonWith(amount: 50)    // → amount: 50 (explicit)
```

### Testing Static Methods with Singletons

**Challenge**: Static methods often use singletons (HttpService, GlobalState) which are hard to mock

**Solutions**:
1. **Refactor to Dependency Injection** (recommended for new code)
2. **Write Integration Tests** (test with real dependencies)
3. **Skip and Document** (agent does this automatically)

```dart
test('returns wallet data', () async {
  final result = await ReferralHttp.getWalletData();
  expect(result, isNotNull);
}, skip: 'TODO: Set up mocks for HttpService singleton');
```
